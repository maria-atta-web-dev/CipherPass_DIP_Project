1. ABSTRACT
================================================================================

This project implements an automated customer screening system for Pakistani banks
and financial institutions. When a person applies to open a bank account, the system
validates their CNIC (NADRA format), checks criminal and fraud databases (AML),
verifies face liveness, analyzes CNIC images for forgery using Digital Image
Processing, and generates a trust score and decision (APPROVE / MANUAL REVIEW /
REJECT). The system demonstrates core DIP concepts including grayscale conversion,
histogram equalization, Gaussian blur, Canny edge detection, CLAHE, and Laplacian
variance. It aligns with State Bank of Pakistan (SBP) customer due diligence
requirements and the Federal Investigation Agency (FIA) criminal screening process.

================================================================================
2. INTRODUCTION & PAKISTAN INDUSTRY CONTEXT
================================================================================

Pakistani banks (HBL, UBL, Meezan Bank, Bank Alfalah) and mobile wallets (JazzCash,
Easypaisa) must verify every customer before account opening. NADRA issues the CNIC
which is the primary identity document. The State Bank of Pakistan enforces
Anti-Money Laundering (AML) rules — banks must screen customers against fraud and
criminal databases. The Federal Investigation Agency (FIA) maintains a criminal and
fraud registry that banks reference during account opening.

Manual verification is slow and cannot detect sophisticated forged CNICs or
photo-based impersonation. This software simulates a branch KYC terminal where the
teller enters CNIC, runs instant AML + FIA criminal lookup, captures face and
documents, and receives a trust score with approve/reject decision.

3. PROBLEM STATEMENT
================================================================================

- Manual KYC is slow at busy branches
- Fake CNIC and tampered documents cause identity fraud
- No single screen showing criminal history + previous verification attempts
- Banks cannot detect duplicate/repeat verification fraud (account takeover)
- Difficulty proving DIP concepts without visible processing steps
- Need for audit trail of each verification (regulatory requirement)

7. AML & CRIMINAL RECORD MODULE
================================================================================

File: customer_screening.py, criminal_records.json

On CNIC lookup:
  1. Search citizen_database.json (bank customers)
  2. Search criminal_records.json (FIA-style criminal watchlist)
  3. Load previous verifications from verification_data/history.json
  4. Detect duplicates: if same CNIC verified 3+ times = fraud alert
  5. Output decision: APPROVE, MANUAL REVIEW, or REJECT

Compliance Officer Actions (ComplianceReviewDialog):
  - REJECT         — Block account opening
  - ESCALATE       — Send to branch manager
  - INVESTIGATE    — Request more documents
  - REPORT_FIA     — Report to Federal Investigation Agency
  - HOLD           — Pending further review

Demo CNICs for testing:
  42101-1234567-1 — Clean customer (APPROVE)
  12345-6789012-3 — Identity fraud + document forgery (REJECT)
  11111-2222222-3 — Bank fraud + money laundering (REJECT)
  54321-0987654-1 — Signature forgery, medium risk (MANUAL REVIEW)
  33201-7777777-7 — SIM fraud + cybercrime (REJECT)
  44401-8888888-8 — ATM card cloning (REJECT)
  43301-1212121-3 — Sanctions violation (REJECT)
  41101-5555555-5 — Loan default + cheque bounce (MANUAL REVIEW)

Trust score penalties:
  - Has criminal record  : -40 points
  - REJECT decision      : -25 points
  - Name mismatch        : -35 points
